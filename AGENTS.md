- Answer language is chosen per request from the Host header (lib/target-language.ts; decks in data/<locale>/); one deployment serves every language domain because Lovable has no per-project build vars.
- Public leaf page metadata uses the shared sitePageHead helper with request-resolved locale; browser-only pages use data-only SSR so domain titles are correct before hydration.
- Kinetic word entrances (framer-motion) must go through usePausableEntrance and the per-page entrance clock in WordSequenceText; framer-motion has no pause, so plain animate props keep playing under overlays.
- Deck text joins the syllables of one word with a single `_` (`ba_lô`); lib/word-joiner.ts turns it into a no-break space when a catalog loads, so the underscore never reaches a reader and the word is never split across lines. Generators and reviewers write the underscore (rules and a paste-in prompt: docs/word-joiner-generation-handoff.md); nothing downstream should strip it from stored decks.
- Vietnamese clue pages are laid out from measured widths (post-player useMeasuredLines + kinetic-text solveMeasuredLines), not the character-count estimate; the estimate only seeds the first, unseen pass. The reader treats a word ending in `,` `.` `;` as a phrase edge (its equivalent of the generator's `|`): never break a line or page one word before or after it (docs/phrase-break-reader-handoff.md).
- Reader-imported packs (lib/custom-pack.ts) live only in browser localStorage and are paged client-side through the shared pure lib/paging.ts; fetchVocabularyPage short-circuits to them, so imports never touch the server or cloud storage.
- Internal bot table reads must remain limited by the existing system-account policies or privileged server access; never restore unrestricted authenticated SELECT policies, because posting configuration and run history are not public feed data.
